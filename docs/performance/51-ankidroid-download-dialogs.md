Code inspection and upstream Anki source reveal three concrete gaps:

1. Anki enables JavaScript immediately before loadUrl. Husk coalesced settings onto a later guest handler message, allowing navigation to race ahead of the JavaScript policy. New hostLoad publishes current settings before navigation on the same serialized native-main queue. Identical settings tuples are not resent; loadData also flushes settings before dispatch. The original deferred setter remains batched for ordinary changes. Phone confirmation is required: no stack or WebKit trace proves this was the only reason for the white page.
2. WebView stored DownloadListener but never delivered it. Native navigation-response handling now routes successful attachments/unrenderable main responses to that listener and reports HTTP errors (including429) to the client's existing error callback. Android DownloadManager was entirely generated stubs: enqueue returned0 and queries returnednull. Handwritten implementation preserves API surface while adding real request destinations/headers, unique IDs,64-bit progress/status/reason queries, exact-once completion broadcast, importable file URI/read access and removal/cancellation. NSURLSession streams to a temporary disk file, copies/moves to the confined imported-app destination without replacing existing files, and runs delegate work at Utility QoS. Late/canceled tasks cannot publish success or delete preexisting failed destinations. HTTP429 remains a failure reason so Anki can offer login. No claim of persistent/background queue recovery or native iOS notification UI is made.
3. Message.obtain(Message), copyFrom, setTarget/setCallback/setWhat, getWhen and peekData were stubs. AppCompat dialog button handling depends on cloning and sending those messages. They now preserve message arguments/handler/callback/async flags and independent Bundle state. Platform AlertDialog also honors supplied button messages and queues dismissal after dispatch, supports legacy overloads and updates already-created button text. These repair actual API contracts; the exact on-device Discard path still needs confirmation.

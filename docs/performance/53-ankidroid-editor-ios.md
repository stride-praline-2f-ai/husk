[Returned observations/excerpts](runs/ANKI-EDITOR-v1.returned-run.json) and [exact packaged library disassembly](runs/ANKI-EDITOR-v1.socket-signal.json) establish a concrete contract defect. Build 160's `libandroidio.so` uses signal 34 (`mov w0/w1, #0x22`) for handler installation and `pthread_kill`. Husk rejects all signals >=32. The reported AsynchronousCloseMonitor EINVAL is therefore expected, not harmless startup noise for a server that must close while accept is blocked.

Read-only upstream review at Anki source `d9bf072f814a0c37d30a694192593b31ff2df875` shows CardViewerFragment destroys its WebView, and CardViewerViewModel.onCleared calls `server.stop()`. NanoHTTPD.stop closes its listening socket then joins its accept thread without a deadline. AOSP libandroidio installs an empty, non-SA_RESTART interrupt handler for bionic reserved `__SIGRTMIN + 2`. Without that interruption, Java close can leave the accept thread blocked and the editor's guest main thread waiting. This fits the returned lifecycle boundary; only the component defect is proven without the physical stack.

Candidate 161 maps this **one** reserved signal to Darwin's otherwise unmapped SIGEMT slot. It extends guest handler indexing and guest/host signal masks, preserving existing SIGUSR1/2, SIGINFO, fault handlers and unsupported RT numbers. No fake close success, skipped server cleanup, changed socket shutdown semantics, periodic polling or forced redraw. The ordinary libandroidio monitor still owns its blocked-thread list and signaled state. Actual shim tests fail against build 160, then pass registration/query, correct original signal delivery, no SA_RESTART, pending/mask round trip and a real blocked accept/thread join on the fixed code.

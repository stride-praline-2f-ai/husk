## Dungeons frame generation, independently optional

Apple MetalFX interpolation needs identified depth/motion/camera inputs, absent in Husk's final-color bridge. Instead of fabricated textures or an inactive toggle, this prototype implements colour-only bidirectional block motion estimation and a separate display-clock presenter. It is NOT MetalFX frame interpolation, native engine motion vectors, a Metal4 game renderer, or proof of60realFPS responsiveness.

- Explicit default-OFF **Dungeons Frame Generation (Beta)** requests30renderedFPS and60Hz presentation. Only the actual Dungeons project with efficient graphics and accepted driver ABI changes the rendered cap. Missing/declined driver keeps the original cap. Normal60realFPS and saved settings remain unchanged when OFF.
- The pinned MoltenVK WSI leases four private BGRA8 offscreen textures. Its scheduled handlers invoke public host proxy methods; these proxy objects never enter Metal's native drawable presentation APIs. The original Vulkan acquire/submit/semaphore/fence/cleanup path remains. Only GPU-completed source frames become eligible inputs.
- A serial presenter owns actual CAMetalLayer drawables. A60Hz CADisplayLink supplies bounded/coalesced ticks; at most two presentation command buffers are in flight and two source frames are queued. Frame history and captured command-completion blocks retain sampled textures until GPU completion. No readback, queue-idle wait, waitUntilCompleted or per-frame disk log.
- On each pair,16pixel-grid block matching uses a two-level bounded search (+/-16pixel coarse plus +/-4pixel refinement) using luma differences in both directions. The middle image warps/interpolates the two colours. Low-confidence/occlusion/cut regions use a real image locally. Fast motion, transparent effects and HUD can still artifact; the search is deliberately bounded rather than an unbounded optical-flow workload.
- Every real frame is then presented after the generated intermediate. Warm-up and input gaps reset history. GPU-completed rendered, actual real/generated drawable callbacks, drops, resets and GPU errors are separately counted. Generated counts include low-confidence real-image fallback; target cadence is not a measured unique-frame or energy claim. Source WSI timestamps are unavailable/zero at lease retirement rather than fabricated display times.
- Pause/resume invalidates epochs and flushes history. Late source completion is rejected. Pool waits are bounded; retired source leases are reusable. GPU/resource failure disables generation and flushes callbacks/history; it does not claim successful60image output. Startup requires384MiB reported process headroom; the four-source texture budget is bounded to96MiB plus small flow fields and existing layer drawables. Extra resources are important given the returned mmapENOMEM.
- This first framegen path uses the custom MoltenVK driver and can retain80%MetalFX spatial. Selecting framegen takes precedence over the separately saved Metal4 beta selector; both are not claimed active together. A Metal4 WSI port of the presenter remains separate future work.

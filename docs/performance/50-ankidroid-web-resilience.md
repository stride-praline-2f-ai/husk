# ANKI-WEB-v1 — host responsiveness and WebView callback ownership

This follows ANKI-PROGRESS-v1 and ANKI-STORAGE-v1. The supplied build157 logs now open the collection at the current container path; settings and CardBrowser (`initCompleted`) work. One run stops making GL frames during replacement of NoteEditor TemplatePreviewer WebViews; another during SharedDecksActivity's network WebView. Heartbeats continue with roughly 5.2–5.5 GiB before jetsam. The second run later handles Home/back and lifecycle changes, so unchanged frame counts alone are not evidence that the whole host is deadlocked: WKWebView renders separately and a static Android UI need not swap. There is no terminal exception or thread stack proving the exact hang cause. Earlier checkpoint-only reports did not locate it.

Concrete code hazards repaired in candidate158:

- WebKit event notification no longer acquires the Java input lock. One atomic pending flag coalesces notifications into the existing phase9 input delivery. The bounded 4096-int input queue has a separate four-int snapshot reserve, so a full touch queue cannot lose the WebKit wakeup. Input and Web event bytes are snapshotted/detached before guest object/string allocation; GC or Java allocation cannot keep those host-facing queue locks held.
- Main-thread WebKit continuations are typed, owned by their WebView and retired before invocation. Teardown cancels that owner's outstanding navigation, dialogs, bridge and resource tasks exactly once. Late/duplicate responses are ignored, scheme tasks cannot be called as blocks and network fallback tasks are canceled with their owner. Completed tasks release their retained network reference.
- Missing automated bridge/navigation responses are canceled after30 seconds; intercepted resources after60 seconds. Human dialogs remain untimed. A single1Hz main-queue timer exists only while timed continuations remain; it stops even when untimed dialogs remain. No new steady-state Web/input polling, per-frame logging or forced redraw was added.

These changes reuse the Dungeons principles of short lock scope, lifetime ownership, bounded pending operations and avoiding idle work. They do not import game worker caps, frame generation or renderer switches into Anki. Existing game graphics/RAM/MetalFX/optional Metal4/framegen mechanisms and Anki's explicitly selected resolution are preserved. The larger2853×2007 surface in the new log has2.25 times the pixels of1902×1338; no silent reduction is applied. Namespace debug spam was investigated but no emitting framework call exists; preserve guest app logs instead of filtering away evidence.

On an output tick it acquires a real drawable and encodes both motion-pyramid generation, both coarse/fine/median flows, quality reduction and full-resolution interpolation on the same queue as real output copies. ## Repair

Reconstruct as soon as GPU-completed source inputs arrive, using a separate bounded preparation queue. Display ticks encode only a cheap copy of the prepared intermediate or the real image, and use the display link's actual near-future CA-clock target. Invalid, stale or distant targets are not scheduled. Coalesced ticks retain the newest target. There is no CPU/GPU idle wait or spin in ordinary gameplay.

No new full-size texture or fifth guest lease: after bidirectional flow ends, motion-pyramid level0 is dead and becomes the prepared output. Interpolation still reads original previous/current guest leases, so there is no read/write alias. Completion of the generated output copy releases the scratch reader before the next preparation may overwrite it. That next preparation can overlap the preceding pair's real-copy slot on the independent output queue. Preparing only after the real slot would artificially lower throughput; sharing one queue would reintroduce head-of-line blocking. Four source leases,96MiB logical texture admission, epoch/GPU-retirement ownership and source output dimensions remain.

Only GPU-completed, ordered, recent source pairs can seed preparation. A per-preparation identity and epoch reject late completions after reset. GPU-held leases remain alive until sampling retires. One writer, one prepared result and the existing bounded ready queue prevent unbounded buffering. Cold/late/reset cases preserve coherent ordering and never display unfinished scratch. A whole-frame quality rejection remains visibly distinct from genuine interpolation; neither a repeated slot nor a build pass is accepted as proof of smooth unique output.

Producer completion host time is now always recorded for freshness, including outside diagnostic capture. It is GPU handoff time, not engine frame-sampling time. Opt-in consumer timing schema3 separates reconstruction from generated/real output copies and records requested display target/source handoff; moving work cannot be mistaken for removing its GPU cost. Pair schema2 retains11 files and marks its generated GPU span as reconstruction. Capture ABI1, source frame identities, bounded staging/pinned output timings/loss counts and manual sharing remain. Mandatory model3 app/actual-loaded-code contract requires this preparation path; no user override or additional toggle.
